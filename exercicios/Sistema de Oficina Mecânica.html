1.Objetivo

Construir, em Java Swing, um sistema em que o funcionário da oficina entra com usuário e senha, cadastra os clientes e seus veículos e registra as ordens de serviço (OS) feitas em cada veículo, do recebimento até a entrega.

O projeto continua o gerenciacontato: usa a mesma organização em camadas (model → dao → service → gui) e acrescenta o que ainda falta à turma.

4.Banco de dados

Script para PostgreSQL. Rode na ordem: as tabelas referenciadas precisam existir antes das chaves estrangeiras.

CREATE TABLE usuario (
    id         SERIAL PRIMARY KEY,
    nome       VARCHAR(100) NOT NULL,
    login      VARCHAR(30)  NOT NULL UNIQUE,
    senha_hash CHAR(64)     NOT NULL,
    perfil     VARCHAR(20)  NOT NULL DEFAULT 'ATENDENTE',
    ativo      BOOLEAN      NOT NULL DEFAULT TRUE
);

CREATE TABLE cliente (
    id       SERIAL PRIMARY KEY,
    nome     VARCHAR(100) NOT NULL,
    telefone VARCHAR(20)  NOT NULL,
    cpf      VARCHAR(14)  UNIQUE
);

CREATE TABLE veiculo (
    id         SERIAL PRIMARY KEY,
    placa      VARCHAR(8)  NOT NULL UNIQUE,
    marca      VARCHAR(50) NOT NULL,
    modelo     VARCHAR(50) NOT NULL,
    ano        INTEGER,
    id_cliente INTEGER NOT NULL REFERENCES cliente(id)
);

CREATE TABLE ordem_servico (
    id                 SERIAL PRIMARY KEY,
    id_veiculo         INTEGER NOT NULL REFERENCES veiculo(id),
    id_usuario         INTEGER NOT NULL REFERENCES usuario(id),
    data_abertura      DATE NOT NULL DEFAULT CURRENT_DATE,
    data_conclusao     DATE,
    descricao_problema VARCHAR(500) NOT NULL,
    servico_realizado  VARCHAR(500),
    valor_mao_obra     NUMERIC(10,2) NOT NULL DEFAULT 0,
    status             VARCHAR(20) NOT NULL DEFAULT 'ABERTA'
);

5.Regras de negócio

Todas ficam na camada service. A tela só chama a service e mostra a mensagem de erro com JOptionPane.

CódigoRegra
RN01Login e senha são obrigatórios na tela de login.
RN02A senha nunca é gravada nem comparada em texto: o sistema calcula o SHA-256 da senha digitada e compara com senha_hash.
RN03Usuário com ativo = false não entra no sistema.
RN04Depois de 3 tentativas de login erradas seguidas, o sistema mostra uma mensagem e fecha.
RN05A mensagem de login inválido é a mesma para usuário inexistente e senha errada (“Usuário ou senha inválidos.”).
RN06Só usuários com perfil ADMIN acessam o cadastro de usuários. A senha do novo usuário tem no mínimo 6 caracteres e precisa ser digitada duas vezes iguais.
RN07O usuário não pode desativar nem excluir a si mesmo.
RN08Nome e telefone do cliente são obrigatórios.
RN09A placa é única e segue o formato antigo (ABC-1234) ou Mercosul (ABC1D23).
RN10Não é possível excluir um cliente que tenha veículos, nem um veículo que tenha OS.
RN11A OS só pode ser aberta para um veículo cadastrado, e guarda o usuário logado em id_usuario.
RN12Ao mudar a OS para CONCLUIDA, o sistema preenche data_conclusao com a data de hoje e exige o serviço realizado e o valor da mão de obra.
RN13Uma OS CONCLUIDA ou CANCELADA não pode mais ser editada.
RN14O valor da mão de obra não pode ser negativo.

Como calcular o SHA-256 em Java 8

Só a biblioteca padrão. O resultado em hexadecimal minúsculo é o que vai na coluna senha_hash.

import java.nio.charset.StandardCharsets;
import java.security.MessageDigest;
import java.security.NoSuchAlgorithmException;

public final class Criptografia {

    public static String sha256(String texto) {
        try {
            MessageDigest md = MessageDigest.getInstance("SHA-256");
            byte[] hash = md.digest(texto.getBytes(StandardCharsets.UTF_8));
            StringBuilder hex = new StringBuilder();
            for (byte b : hash) {
                hex.append(String.format("%02x", b));
            }
            return hex.toString();
        } catch (NoSuchAlgorithmException e) {
            throw new IllegalStateException("SHA-256 indisponível", e);
        }
    }
}

// Criptografia.sha256("admin123")
// → 240be518fabd2724ddb6f04eeb1da5967448d7e831c08c8fa822809f74c720a9

O usuário logado fica guardado numa classe Sessao com um atributo static, para qualquer tela saber quem está usando o sistema:

public final class Sessao {
    private static Usuario usuarioLogado;

    public static void iniciar(Usuario usuario) { usuarioLogado = usuario; }
    public static Usuario getUsuario()          { return usuarioLogado; }
    public static boolean isAdmin()             { return usuarioLogado.getPerfil() == Perfil.ADMIN; }
    public static void encerrar()               { usuarioLogado = null; }
}
Para discutir em sala: SHA-256 puro é suficiente para aprender o conceito de não guardar senha em texto. Em sistemas reais usa-se um algoritmo lento e com salt, como bcrypt ou PBKDF2.

AutenticacaoService.entrar(login, senha) busca o usuário pelo login (UsuarioDAO.buscarPorLogin), compara o hash, verifica se está ativo e devolve o Usuario ou lança uma exceção com a mensagem da RN05.

9.Extras (para quem terminar antes)

  • Cor na linha da T06 conforme o status, com TableCellRenderer.
  • JFormattedTextField com máscara para telefone, CPF e placa.
  • Tela “Alterar minha senha”, pedindo a senha atual.
  • Total faturado no mês (soma das OS concluídas), mostrado na barra de status.
  • Histórico do veículo: todas as OS de uma placa.
  • Tabela item_os (id_ordem_servico, descrição, quantidade, valor) para peças; total da OS = mão de obra + peças.

10.Critérios de avaliação

  • Login funciona com senha em hash, perfil e limite de tentativas (RN01–RN05).
  • Cadastro de usuários acessível só para ADMIN (RN06, RN07).
  • Clientes, veículos e OS com incluir, listar, editar e excluir.
  • Chaves estrangeiras no padrão id_<tabela> e JOIN nas listagens de veículos e OS.
  • Regras de negócio na camada service, não na tela.
  • Mensagens de erro claras com JOptionPane.
  • Código organizado nas pastas da seção 7.
  • Pelo menos um extra (ponto adicional).
